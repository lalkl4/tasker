# Tasker

Самохостимый трекер задач. Поднимаете сервер у себя — работаете с одними и
теми же задачами из браузера и с телефона.

Это **сборочный репозиторий**: он ничего не компилирует, а описывает, какие
версии каких образов работают вместе. В нём и лежит ответ на вопрос «что
сейчас развёрнуто», в виде текста под контролем версий.

| Репозиторий | Что там |
|---|---|
| [tasker-api](https://github.com/lalkl4/tasker-api) | сервер: FastAPI, SQLAlchemy, миграции |
| [tasker-web](https://github.com/lalkl4/tasker-web) | веб-клиент |
| tasker-mobile | клиент на Flutter *(в работе)* |
| **tasker** | этот репозиторий: compose, Caddy, скрипты, документация |

## Запуск

```bash
git clone https://github.com/lalkl4/tasker
cd tasker
cp .env.example .env
```

В `.env` обязательно задайте `TASKER_DB_PASSWORD` и `TASKER_DOMAIN`. Затем:

```bash
make up
```

Домен должен уже указывать на этот сервер — Caddy сам получит сертификат
Let's Encrypt. Для локальной пробы оставьте `TASKER_DOMAIN=localhost`:
сертификат подпишет внутренний УЦ, браузер поругается, это нормально.

Первый зашедший регистрируется сам. Когда все свои завелись, поставьте
`TASKER_ALLOW_REGISTRATION=false` и `make restart`.

## Что из чего состоит

```
        :80 :443
           │
        ┌──▼───┐   /            ┌─────┐
        │caddy ├───────────────▶│ web │  статика, nginx
        │  TLS │   /api/*       └─────┘
        └──┬───┘   /.well-known/tasker
           │       /docs
           └───────────────────▶┌─────┐     ┌────┐
                                │ api ├────▶│ db │  PostgreSQL
                                └─────┘     └──▲─┘
                              ┌─────────┐      │
                              │ migrate ├──────┘  разовая задача,
                              └─────────┘         api ждёт её завершения
```

Веб и API живут под одним доменом, поэтому браузер ходит относительными
путями и CORS в его случае не участвует вовсе.

## Команды

```
make help      список команд
make up        поднять стек
make ps        состояние сервисов
make logs      логи
make version   какая версия развёрнута и что реально отвечает

make update VERSION=1.4.3   обновиться
make rollback               вернуться на предыдущую версию

make backup                 снять дамп
make restore FILE=...       восстановить из дампа
make dev                    локальная разработка с автоперезагрузкой
```

## Обновление

```bash
cd /opt/tasker
make update VERSION=1.4.3
```

Под этим — последовательность, которую всегда можно выполнить руками:

1. **дамп базы** — до миграций, иначе восстанавливаться будет не из чего;
2. текущая версия запоминается в `.env.previous`;
3. `TASKER_VERSION` в `.env` меняется на новую, образы забираются;
4. `docker compose up -d --wait` — миграции отрабатывают как зависимость
   сервиса `api`, а `--wait` дожидается healthcheck и возвращает ошибку,
   если стек не поднялся;
5. проверка, что сервер отвечает.

Обратите внимание: `docker compose down` в этой последовательности нет.
`up -d` пересоздаёт только те контейнеры, у которых изменился образ или
настройки, а `down` погасил бы заодно и базу, которая обновляться не
собиралась.

## Откат

```bash
make rollback
```

Возвращает предыдущую версию образов. **Схема базы при этом остаётся новой** —
миграции не отменяются. Это штатно при соблюдении правила: миграция версии N
обязана быть совместима с кодом версии N−1. Подробно, с примером на четыре
выпуска, — в [docs/versioning.md](docs/versioning.md).

Если правило нарушено и старый код с новой схемой не работает, откат делается
через восстановление дампа:

```bash
make restore FILE=tasker-20260821-030000.sql.gz
```

## Настройки

Все в `.env`, см. [.env.example](.env.example) с пояснениями.

| Переменная | Смысл |
|---|---|
| `TASKER_VERSION` | что развёрнуто; меняется через `make update` |
| `TASKER_DOMAIN` | домен; от него зависит выпуск сертификата |
| `TASKER_DB_PASSWORD` | пароль PostgreSQL, обязательно свой |
| `TASKER_JWT_SECRET` | пусто — сервер сгенерирует сам |
| `TASKER_CORS_ORIGINS` | нужен мобильному клиенту, браузеру нет |
| `TASKER_ALLOW_REGISTRATION` | `false` закрывает регистрацию |
| `TASKER_KEEP_BACKUPS` | сколько дампов хранить |
